# Siderostat v0.4.1

## Changes

- Wire production two-node DS4 tensor-parallel startup and bounded recovery, including RDMA readiness and the V4.1 Flash model profiles.
- Improve TP child cleanup, shutdown progress reporting, standalone recovery, and interruption reporting for incomplete generation streams.
- Interrupt active proxy requests during runtime shutdown and avoid forcibly killing a still-running runtime from the installer.

## Compatibility and acceptance

- The operator accepted the release quality after two-node testing with MacBook Pro M5 Max and Mac Studio M4 Max, DeepSeek V4.1 Flash 1017 Q2, and RDMA TP. Build 38 passed a generation-time Thunderbolt disconnect, standalone recovery on both nodes, and TP recovery after reconnect. Build 39 returned to TP Ready on both nodes and completed a short generation.
- The normal SIGTERM stream interruption and owned-child reaping were verified in an isolated process. The build 39 normal-SIGTERM path during generation was not tested on the two physical machines.
- The LaunchAgent requests `ExitTimeOut=600`, but `launchctl print` reported an effective 60 seconds on both tested Macs. Long management operations, stuck clients, or child cleanup can exceed that deadline; startup-time SIGTERM before the servers start is also outside the isolated verification.
- Model files, local paths, credentials, caches and runtime state are not included. Validate the DS4 source, binary, model and RDMA configuration before changing them.

## macOS artifacts

Build 40 is produced from the annotated release tag. The pkg and DMG are Developer ID signed with `timestamp_mode=none`, `notarization=skipped`, and `distribution_ready=false`, as required by the 0.x policy. They are not notarized distribution-ready artifacts. Both nodes must use the same compatible release and model configuration.

## Recovery

The uninstaller preserves user data. Finish active requests before upgrades; the previously installed LaunchAgent's stop deadline governs its shutdown. Even with no requests in flight, a slow child may outlive that deadline. Verify that runtime and managed children have stopped before retrying an interrupted upgrade.
