# siderostat v0.1.0

Status: release candidate

## Highlights

- modeだけで転送先を一意に決めるstreaming reverse proxy
- Solo Standalone、Paired Standalone、Distributed MXFP4の3 mode
- Thunderbolt Bridge固定address、HMAC control lease、peer ingress認証
- 実DS4 HELLO、deployment manifest、complete routeによるfail-closed promotion
- Q2-Q4 resident Standaloneでのtyped DSpark設定、fingerprint、activation確認
- standalone/distributedを分離したKV namespace
- owned DS4 child supervision、safe drain、restart recovery
- local admin CLI/API、structured log、Prometheus metrics、macOS LaunchAgent

## Verified production profile

- DS4 source: `b0309611041655f4e45671cfd9c9886aff161406`
- Mac Studio coordinatorとMacBook Pro workerの機種別native DS4 binary pair
- Q2-Q4 resident / SSD streaming Standalone
- MXFP4 SSD streaming Standalone
- MXFP4 Distributed（実HELLO、8K prefill、10回promotion/demotion）
- Q2-Q4 resident StandaloneのDSpark activationとshort request

## Migration and rollback

Schema v1のload-balancer configは自動変換せず、legacy fieldを列挙して拒否する。旧affinity SQLiteは読まず、変更せず、削除しない。Schema v2 configはlegacy configと別pathに配置する。

P7-02でrelease candidateへのupgrade、直前binaryへのrollback、candidateへの再upgradeを行い、各段階でSolo Standalone readinessへ復帰した。詳細は [`migration-rollback-2026-08-11.md`](../compatibility/migration-rollback-2026-08-11.md) を参照する。

Rollback refとして`legacy/load-balancer-v1` branchとannotated tag `load-balancer-v1-final`を保持する。

## Known limitations

- 2 node固定で、role addressは`10.99.0.1` / `10.99.0.2`
- standalone/distributed切替中は短い503 windowがある
- Worker requestはcoordinatorまでproxyを2 hopする
- Peer proxy bodyとDS4 native trafficは暗号化されない
- standalone/distributed間でlive KVを引き継がない
- DS4 wire/log/CLI互換性は承認済みbaselineへ固定する
- DSparkはresident Standalone限定で、Distributedでは有効化しない
- Q2 residentは任意profileで、v0.1.0 production profileには含めない
