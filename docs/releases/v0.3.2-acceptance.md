# siderostat v0.3.2 acceptance

Status: PASS / RELEASE PUBLISHED

## Scope

v0.3.2 は macOS 27.0 で Dynamic Store の network-change notification が再接続処理へ
届かず、Solo Standalone から自動ペアリングできない問題を修正する patch release である。

## Automated verification

```sh
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-targets
cargo check --workspace --locked
git diff --check
```

変更固有のテストは、absolute Dynamic Store path の regex と空の `keys` 配列を固定する。
モデル、secret、runtime state、cache、実 DS4 child はテスト対象に含めない。

## Release identity

- Version: `0.3.2`
- Release branch: `hotfix/0.3.2/macos-27-reconnect`
- Hotfix implementation revision: `b4f93ef` (`fix: restore macOS network event notifications`)
- Release tag: annotated `v0.3.2`
- Official distribution: source-only
- macOS app/pkg: この hotfix では作成・配布しない

## Two-node acceptance

両ノードを同じ v0.3.2 source revision へ更新し、次を確認する。

1. `bridge0` の IPv4 が各ノードで `10.99.0.1/30` と `10.99.0.2/30` になる。
2. 両ノードの `/healthz` と `/readyz` が ready を返す。
3. 起動直後の baseline として `solo-standalone-ready` を経由する。
4. 自動ペアリング後、Coordinator と Worker の control session が相互に paired になる。
5. 設定済み policy に従い、Distributed mode へ遷移する。

## Field evidence

実機検証日: 2026-09-16 JST。両ノードを同じ v0.3.2 source revision から build・install・start した。

| Check | MacBook Pro | Mac Studio |
|---|---|---|
| `bridge0` IPv4 | `10.99.0.2/30` | `10.99.0.1/30` |
| `/healthz` | HTTP 200, version `0.3.2` | HTTP 200, version `0.3.2` |
| `/readyz` | HTTP 200, `status=ready`, `admission=serving` | HTTP 200, `status=ready`, `admission=serving` |
| final cluster mode/state | `distributed-layer-parallel` / `distributed-ready` | `distributed-layer-parallel` / `distributed-ready` |
| role / phase | worker / `worker-ready` | coordinator / `worker-ready` |
| control session | `peer-present=true` | `peer-present=true` |
| LaunchAgents | runtime／monitor `running` | runtime／monitor `running` |

インストール済み runtime／monitor の SHA-256 は各ノードの release build と一致し、両バイナリの
`codesign --verify` は成功した。検証時点で、MacBook Pro は standalone から distributed worker へ、
Mac Studio は paired standalone から distributed coordinator へ自動遷移し、最終的に両ノードが
`distributed-ready` で admission `serving` となった。
