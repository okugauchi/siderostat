# siderostat v0.2.1 acceptance

## Status

Status: **PASS / RELEASE FINALIZED**

`259b575`を実装基準として、Required CI、release build、candidate artifact、2-node installation、
H-03片側process restart、H-02物理cable、H-04 macOS restartを2026-08-18から19日に再検証した。
両nodeへの再install後はfull GGUF rehashなしで`DistributedReady`へ復帰し、`allow_sigkill=true`を
含む生成config、LaunchAgent、admin APIも正常だった。

H-03はcoordinator-only 2回、worker-only 2回の全cycleが、手動pair/reconcile、state削除、force killなしで
新しいchild PID/generationの`DistributedReady`へ収束した。旧候補で発生した
`SIGKILL is not allowed for this child`、409 loop、stale/orphan childは再発していない。

H-04はcoordinator-only、worker-only、両node同時restartの3 scenarioを2026-08-19に実施し、
約2分28秒から3分35秒で両nodeの新しいdistributed childへ自動収束した。全scenarioで最終
`DistributedReady`、admission serving、doctor healthy、public `/v1/models` HTTP 200を確認し、
手動復旧、409 loop、SIGKILL拒否、stale/orphan childはなかった。

一方、coordinator-only restartではworker childの停止完了まで約180秒かかり、その間coordinatorが
SoloとPairedを反復した。最終的には自動解消するためH-03の安全性・復旧判定はPASSとする。
対応する「Standalone起動」「ノード検出」通知が有限回反復し得るUXリスクは2026-08-19にoperatorが
v0.2.1で明示的にacceptし、後続改善へ送った。H-02物理cable detach/reconnectは2 cycle連続PASSした。
全operator gateをcloseし、`main`の確定source `34667ea`を指すannotated `v0.2.1` tagから
final artifactを生成・監査したため、release全体をPASSとする。

### Coordinator restart時の有限Pairing反復

Coordinator-only #2では、workerが旧distributed childを停止している間、coordinatorが
`SoloStandaloneReady`と`PairedStandaloneReady`を約25秒周期で反復した。13:26:29Zから
13:28:59Zまでに`pairing-ready`を7回記録し、一部のpromotion preflightはworkerの
`SoloStandaloneStarting`に対してHTTP 500となった。13:29:02ZにworkerがSolo readyとなった後は
通常のpairing/promotionへ進み、13:30:01Zまでに両nodeがDistributedReadyへ収束した。

この反復は旧configのような停止不能・無限loopではなく、180秒のstop timeoutと
`allow_sigkill=true`によって有限に解消する。安全性・最終収束・orphan不在というH-03完了条件は
満たすためPASSを維持する。通知serviceのthrottleは5秒で、Solo/Paired安定状態を双方通知対象と
するため、試験中に複数の「Standalone起動」「ノード検出」通知が表示され得る。

Operatorは2026-08-19に、この有限反復をv0.2.1の既知UXリスクとして明示的にacceptした。
状態機械とserving safetyへの影響がなく、全実機scenarioが手動復旧なしで収束したことを根拠とする。
発生経緯、再現方法、後続のsemantic deduplication提案は
[`coordinator-restart-notification-repetition-2026-08-19.md`](../research/coordinator-restart-notification-repetition-2026-08-19.md)
に記録した。

### H-04 macOS restart evidence

2026-08-19にcoordinator-only、worker-only、両node同時の順でmacOSを再起動した。各scenarioの
開始前に両nodeが`DistributedReady`、admission serving、in-flight 0、lease valid、peer-presentで
あることを確認した。手動pair/reconcile、state削除、force killは行っていない。

| Scenario | Shutdown / boot evidence | Final Distributed checkpoint | Final distributed PID |
|---|---|---|---|
| Coordinator-only | shutdown 16:54:45、boot 16:55:09 JST | 16:58:07 JST、約3分22秒 | worker 10103、coordinator 1134 |
| Worker-only | shutdown 17:01:38、boot 17:01 JST | 17:04:06 JST、約2分28秒 | worker 1945、coordinator 1342 |
| Both nodes | shutdown 17:07:24–26、coordinator boot 17:07:42、worker boot 17:07 JST | 17:10:58 JST、約3分35秒 | worker 1494、coordinator 1061 |

Coordinator-onlyでは非再起動側workerがpeer loss後にroleを`Worker`から`Unknown`へ再判定し、
worker-onlyでは非再起動側coordinatorが`Coordinator`から`Unknown`へ再判定した。いずれも
LaunchAgentのrole適用restart、Solo serving、role復帰、Pairing、promotionを経て自動収束した。
両node同時restartではworker 17:09:04、coordinator 17:09:42 JSTにSolo readyとなり、17:09:47–49に
Pairing、17:09:57にpromotionを開始し、17:10:58にcoordinatorのcomplete routeがreadyとなった。

最終checkpointはworker cluster generation 374、coordinator cluster generation 841、control session
generation 833だった。両nodeでleaseはvalid、peer-present、route-scoped、admission serving、
in-flight 0、doctor healthyで、healthz、readyz、public `/v1/models`はすべてHTTP 200だった。
LaunchAgentは両node各1 jobで、試験時間帯に409、`SIGKILL is not allowed for this child`、
unknown/orphan process、manual interventionはなかった。

H-04中はHermes cron failure対策の運用overlayとして、coordinatorの
`proxy.timeouts.first_body_byte`と`stream_idle`を2400秒、workerを従来どおり1200秒で維持した。
`cluster.*`、`ds4.allow_sigkill`、binaryはH-03/H-02検証時から変更していない。H-04はin-flight 0で
実施しており、このproxy request timeout差はmacOS再起動後のrole判定・Pairing・promotionを妨げなかった。
