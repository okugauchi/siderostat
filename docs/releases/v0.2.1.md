## Changes since the previous candidate

- deployment manifest不一致後にperiodic reconcileがpairing blockを迂回する問題を`53aaa9c`で修正し、
  merge commit `ef4c274`を経てrelease ancestryへ収録した。
- 不一致時は両nodeをSolo Standaloneへ収束させ、通知とfailure contextを保持したまま自動pairingと
  child restartを抑止する。
- GGUF digest cacheへ最大4 MiBの分散サンプル署名を追加した。size不変のmetadata driftはsample一致時に
  full SHA-256を再計算せずcache metadataを更新する。
- sampleを持たない旧cacheはmetadata完全一致時に自動upgradeする。metadata driftがある旧cacheだけ
  `--accept-model-metadata-change`による明示的なoperator確認を要求する。
- size変更またはsample不一致はoperator overrideを許可せず、full fingerprintを必須とする。
- identity確認済みowned DS4 childをSIGTERM後に確実にreapできるようにし、生成configの
  `allow_sigkill=true`と組み合わせて片側restartから自動復旧する。
- `cargo xtask install --start`は既存LaunchAgentの`bootout`完了を待ってから`bootstrap`し、
  status 5となる再install raceを回避する。
- Hermesの1,800秒stale timeoutよりproxy側が先に切断しないよう、install生成configの
  `first_body_byte`と`stream_idle`の既定値を2,400秒へ延長する。

## Validation summary

2026-08-18のall-feature再試験ではproduction reconnect 37件がPASSし、10-cycle
Paired/Distributed cable blip、100-session Pair timing、deployment mismatch latchを含む。
Thunderbolt直結2 nodeへ`259b575`をinstallした実機試験では、両nodeが`distributed-ready`へ収束し、
`cargo xtask verify`、doctor、public `/v1/models`がPASSした。不一致manifest試験でも、不一致検出から
手動停止まで再pairingとchild restartが発生せず、旧release blockerの修正を確認した。

`cargo xtask install`では旧digest cacheへ4つのsample署名が追加され、約156 GBのMXFP4を含むGGUF
full SHA-256の再計算を行わずに完了した。Thunderbolt 5 cableのdetach/reconnectも2 cycle連続で
検証し、各cycleでSolo servingへ安全に復帰後、再接続から約1分で新しいchildのDistributedReadyへ
自動収束した。

旧候補で判明した`allow_sigkill=false`の停止不能は修正済みである。`259b575`を両nodeへ再install後、
H-03 coordinator-only 2回、worker-only 2回を実施し、全cycleが新しいchild PID/generationの
DistributedReadyへ自動収束した。409、SIGKILL拒否、stale/orphan childは再発していない。

H-04はcoordinator-only、worker-only、両node同時macOS restartの全3 scenarioがPASSした。
各scenarioは手動復旧なしで約2分28秒から3分35秒以内に新しいdistributed childへ収束し、
最終doctor、healthz、readyz、public `/v1/models`は両nodeで正常だった。

Coordinator-onlyではworker childの停止完了まで約180秒かかり、その間Solo/Paired遷移が有限回反復した。
最終収束と安全性はPASSである。対応する「Standalone起動」「ノード検出」通知が反復し得るUXリスクは
2026-08-19にoperatorがv0.2.1で明示acceptし、発生経緯、再現方法、semantic deduplicationによる
改善提案をresearch文書へ記録した。

実DS4 Prefill中のmonitor表示は同日のHermes cron対策確認中にoperatorが目視確認した。直近でmonitor
表示改善を予定しているため、この時点の追加artifactはrelease gateに要求しない。Upgrade→rollback→
re-upgradeは現在稼働中binaryで同じ配備・再起動processを確認済みとして、operator判断で再実施を免除した。

## Accepted limitations

- macOS `.app` / `.pkg`、RDMA over Thunderbolt、Tensor Parallelは対象外。
