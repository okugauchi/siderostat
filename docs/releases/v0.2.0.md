## Reconnect and distributed inference

### PeerLost recovery

control reconcile と route-loss monitor は共通の recovery owner を使用する。recovery は admission を
閉じ、identity を確認した owned distributed child を停止し、standalone readiness が成立してから
`SoloStandaloneReady`、`LocalStandalone`、serving を公開する。重複・古い generation・route-loss
との競合は冪等に収束し、停止または起動失敗時に Ready 状態を偽装しない。

### Control session negotiation

coordinator は `/v1/node` で得た peer generation を入力として Pair offer/confirm を行い、既知の
session generation を下げずに両 node を同一 session へ収束させる。cluster generation と control
session generation は別 field のまま永続化され、旧 state fixture は cluster generation まで安全に
normalize される。古い non-Pair command と generation mismatch は引き続き拒否される。

### Network and failure recovery

production control path の固定 `route_scoped=true` は、最新 epoch の `NetworkEvidence` に置き換えられた。
Bonjour の存在だけでは peer present とせず、address、subnet、`bridge0` scoped route、認証、lease、
stability が揃うまで promotion しない。Backoff の期限後は periodic reconcile が一度だけ Paired へ戻し、
Backoff 中に peer を失った場合は Solo recovery を優先する。

deployment manifest の不一致を両 node の Solo Standalone へ収束させ、自動 pairing を停止することが
仕様上の挙動である。ただし現 release candidate では periodic peer reconcile が停止 latch を迂回する
実機不具合が確認されており、`53aaa9c` の取り込みと再 acceptance を release gate とする。

## macOS operations and observability

- `siderostat-monitor` を別 crate・別 process として追加した。cluster mode/state、node identifier、
  target readiness、Prefill、KV cache、Decode throughput を loopback admin API から取得する。
- worker が Paired/Distributed の場合は、既存の認証済み control plane を介して coordinator metrics を
  取得する。coordinator の admin API を Thunderbolt Bridge へ公開しない。
- menu bar から runtime restart、monitor restart、両 LaunchAgent の終了を実行できる。
- macOS 通知は Aqua GUI session で非同期に投稿し、通知失敗を cluster 動作へ波及させない。
- startup cleanup は既存 process を検出すると通知後に identity を再確認し、owned process だけを停止する。
  自動 cleanup は config または CLI で拒否できる。
- `/cluster` と `cluster status --json` に cluster/control generation、lease、phase、child identity を追加し、
  Pair 409 や recovery/promotion の開始・完了・失敗を redaction 済み構造化 log へ記録する。

## Installation and deployment

`cargo xtask` に `fingerprint-models`、`install`、`verify`、`uninstall` を追加した。install は runtime と
monitor の release build・ad-hoc codesign、config/manifest/secret の生成、plist lint、LaunchAgent 配置を
行い、再実行しても既存 secret を上書きしない。GGUF digest は専用 cache へ事前記録でき、install ごとの
大容量 model 再読込を避けられる。

secret の標準名は拡張子なしの `cluster-control`、`peer-proxy`、`admin` へ変更した。既存 config が
旧 path を明示している場合はそのまま利用でき、`xtask install --shared-secret-dir` は migration 入力として
legacy `.key` 名も受け付ける。

本 release の配布形態は引き続き standalone binary と `gui/<uid>` LaunchAgent である。macOS
Application Bundle と Installer package (`.pkg`) は含まれない。

## Runtime and proxy changes

- production runtime、coordinator、process supervisor、serve startup を責務別 module へ分割し、
  supervised child slot を共通化した。
- role address が取得できない場合は startup failure にせず `Unknown` とし、production runtime を作らない。
  network 変化または cluster restart で role を再検出し、role 変更時は runtime を再生成する。
- transient な macOS process enumeration/inspection race を retry 可能として扱い、unknown process へ
  無承認で signal を送らない。
- example config の `max_in_flight` は `2`、response header timeout は `3600s` へ拡張した。
  transition 中の HTTP 503/504 を Siderostat 自身が別 mode で再試行することはない。

## Migration and rollback

- 永続 state schema version は据え置きで、追加した `control_session_generation` がない旧 state を読み込める。
- secret file は config の明示 path が正本であり、拡張子なし標準名への即時 rename は必須ではない。
- manifest または binary compatibility 集合を変更した場合は、両 node を同時に再生成・配布する。
  片側だけの更新は fail closed で Solo Standalone へ収束する。
- reconnect 実機検証では旧 binary/config/state/plist を削除せず rollback 用に保全した。operator は
  検証済み candidate の継続利用を承認し、rollback は実施していない。
- v0.1.0 からの独立した upgrade→rollback→re-upgrade rehearsal は本範囲では再実施していない。

## Known limitations

- 対応 topology は固定 address の Thunderbolt Bridge で接続した 2 node に限定する。
- DS4 と model の production compatibility は既存の `b030961...` acceptance baseline に固定する。
- DSpark は resident Standalone 限定で、Distributed coordinator/worker argv では有効化しない。
- monitor の parser/state/compile gate は PASS だが、実 DS4 の Prefill 中表示を確認する Phase 5 は未実施。
- desktop notification は Aqua GUI session を必要とし、LaunchDaemon または非 GUI session では表示しない。
- transition 中は短い HTTP 503 window があり、request の自動再実行は行わない。
- deployment mismatch 時の restart loop 修正 `53aaa9c` は release candidate artifact に未収録である。
- peer proxy body と DS4 native traffic は暗号化せず、専用の物理接続を trust boundary とする。
- macOS `.app` / `.pkg`、RDMA over Thunderbolt、Tensor Parallel は本 release の対象外である。
