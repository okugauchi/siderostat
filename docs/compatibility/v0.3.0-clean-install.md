Before the first-launch test, `launchctl print gui/501/dev.siderostat-ds4-proxy.runtime`
reported `running` on the MacBook Pro and no such service on the Mac Studio. The
MacBook Pro therefore has a pre-existing `SMAppService` registration from the
previous application exercise and does not qualify for the clean pre-first-launch
registration check until the service is stopped/unregistered. The Mac Studio is
the clean candidate for that check.

The earlier package-install attempt was not accepted as evidence because macOS
relocated its component into an existing development workspace bundle. The
package builder was corrected to use a staged `--root` payload and a component
plist with `BundleIsRelocatable=false`; the artifact above is the corrected
package.

Both Macs reported `AppleLanguages=("ja-JP")`. The MacBook Pro English-notification
issue was caused by Foundation's automatic bundle localization selection choosing
English even though Japanese was the system preference. Monitor and
`siderostat-runtime` now pass the system language preferences explicitly when
resolving `Localizable.strings`.

The refresh callback no longer holds the shared display-state mutex while querying
`SMAppService.status()`. Service status is cached for five seconds, so a healthy
runtime can update the menu bar instead of remaining in the offline state.

User-visible terms are fixed as follows:

- `Siderostat`: the menu-bar application.
- `siderostat-runtime`: the resident supervisor and auto-start target.
- `ds4-server`: the actual inference process.

The prior build 1/build 2/build 4 observations remain historical. Build 5 was the
previous candidate; build 6 below supersedes it for the next E-04 review.
