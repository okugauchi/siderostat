反復中にproduction wiring固有の境界条件を検出して修正した。具体的には、node間generationの独立性、workerのBeginDrain二重drain、手動demotionとroute-loss monitorの競合、worker停止完了前のDemote応答、SIGKILL後のreaping時間を含まない短いHTTP timeoutによる副作用future cancel、降格後のcoordinator control phase残留である。Lifecycle副作用は独立taskで完遂し、`stop + sigkill_reap_window + peer_request`のtimeoutで応答を待つ。計画再起動の失敗時は、両childの停止成功後にだけ`Demoting`へ遷移し、peer停止失敗時は分散routeの完全復旧を待たず、local standalone と admission を復旧して `PairedStandaloneReady` に戻す。Demote成功後は両control phaseを`Paired`へ戻す。

実DS4 distributed workerはSIGTERMだけでは停止しなかったため、受入configでは`allow_sigkill=true`、`stop=5s`を使用した。SIGKILL対象はproxyがspawnし、PID、canonical executable、argv hash、process start timeをsignal直前に再検証できたowned process groupだけである。Bonjour discoveryはこのacceptanceの対象外で、static fixed-address discoveryを使用した。
