# H04 未達改善 実装計画

## 目的

H04で未達だった次の契約を、`feature/v040-integration` の本番経路へ接続する。

1. Force policy は再起動後も保持し、片側適用を成功扱いしない。
2. Force は両nodeのprepare・drain・child停止・Solo ready・commitを経て完了する。
3. 分散childの異常終了を検出し、安全状態へ遷移して自動復旧する。
4. menuの完了表示、policy job、`/cluster` の実値を一致させる。

## 既存設計の利用

- `PolicyJournal` のatomic state保存を起動復元とForce/Automatic intentへ接続する。
- `PolicyControlRequest` のprepare/commit/abortと既存HMAC control channelをpeer通信に使う。
- `ForceApplyCoordinator` を二nodeのphase判定に使い、別の状態機械は追加しない。
- `WorkerDistributedRuntime::wait_for_failure` を本番監視タスクから呼び出す。
- reducerの既存イベントを利用し、child lossはadmission停止・route無効化を先に行う。

## タスク

### P0: 永続化と誤成功防止

1. 起動時にPersistentClusterStateをProductionClusterRuntimeへ注入する。
2. `operator_policy`、`applied_policy`、`policy_epoch`、`pending_operation` を復元する。
3. Force/Automaticのintentを副作用前に保存し、失敗時は副作用を行わない。
4. policy jobのnode結果を実際の両node結果に基づけ、片側ackでは`running`または`failed`にする。
5. P0のREDテストを追加し、復元・partial policy・epoch不一致を再現する。

### P1: Force transaction

1. Force開始時にoperation IDとepochを確定する。
2. local/peerへsigned prepareを送り、両側journal保存を確認する。
3. 両側の新規promotionを停止し、in-flightをdrainする。
4. 分散childを停止してSolo readyを確認する。
5. 両側のapplied ack後だけjournalをAppliedへ更新し、jobをcompleteにする。
6. timeout・peer不在・epoch不一致はpending/failedとして残し、Automaticへ自動復帰しない。

### P2: child監視

1. distributed worker/coordinator ready後に監視タスクを起動する。
2. child終了時はadmissionを停止し、proxy targetを無効化する。
3. 認証済みcontrol経路でpeerへchild loss/demoteを通知する。
4. `DistributedReady` と child running/identityの不一致を診断上もready扱いしない。
5. policy epochとpeer状態が揃った後だけAutomatic再昇格を許可する。

### P3: menu契約

1. menuが返却されたjob IDをpollする契約を明文化する。
2. job complete後に`/cluster`を再取得し、実際のpolicy/epoch/stateを表示する。
3. partial、timeout、peer不在を成功表示しない。
4. CLI/APIの受入テストを追加する。

## テスト順序

各項目はRED→GREEN→REFACTORで進める。

1. P0 unit/integration tests
2. P1 policy control and production runtime tests
3. P2 fake lifecycle child-crash tests
4. P3 API/job contract tests
5. `cargo fmt --check`
6. `cargo clippy --all-targets --all-features -- -D warnings`
7. `cargo test --all-targets`

## H04再受入

同一v0.4.0候補を両nodeへ配置し、次を実機で確認する。

- distributed-readyからForceで両nodeがSoloへ収束
- runtime再起動後もforced-standaloneとepochを保持
- Automaticでdistributed-readyへ復帰
- worker child強制終了後、手動demoteなしで安全fallback/再生成
- menu、job、`/cluster`のpolicy表示が一致
- partial policyがcompleteにならない
