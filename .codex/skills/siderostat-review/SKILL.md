# Siderostat Review

Siderostat の開発項目（feature / fix / refactor）について、実装完了報告の**前に**レビューを実施するための枠組み。CONTRIBUTING.md の「Review と merge」基準を、具体的で検証可能な観点へ展開する。

## いつ使うか
- 開発項目の実装完了を報告する直前（レビュー → 修正・追加実装 → 再レビュー まで含めて完了させる）
- ユーザーが「レビューしてから報告してほしい」と明示した場合
- 新機能・新フラグ・新モード・新抽象を導入する開発項目で、影響範囲の封じ込めが特に重要

## ワークフロー
1. **対象の特定**: レビュー対象の変更範囲（仕様・影響ファイル・導入する新概念）を把握する
2. **汎用観点の適用**: [references/axes.md](references/axes.md) を読み、7 つの汎用観点を対象に適用する
3. **蓄積観点の適用**: [references/registry.md](references/registry.md) を読み、過去の開発項目で蓄積されたプロジェクト固有観点を適用する
4. **指摘の整理**: 指摘を重大度付き（M: 中 / m: 低）で列挙し、観点 ID と対応方針を対応付ける
5. **修正と再レビュー**: 指摘に基づき修正・追加実装し、再レビューする。実装完了報告前にこのループを閉じる
6. **観点の成長**: 今回のレビューで新たに汎用化できる教訓（特定機能に閉じないもの）を registry に追記し、レビュー結果を記録する

## 重要な制約
- レビューは「実装完了報告前」に行い、修正・追加実装・再レビューまで含む
- 特定機能（dry-run 等）に閉じた観点をそのまま持ち込まず、汎用観点へ一般化する
- 新規観点は今後どの開発項目にも適用できる形で registry に追加する
- 検証は実際に実行して PASS を確認してから完了を報告する（cargo fmt --check / clippy / test）
- ユーザー所有の変更（本タスクと無関係の編集）には触れない
