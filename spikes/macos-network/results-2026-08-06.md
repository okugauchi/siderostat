## Build

`network_probe.c` compiled with `xcrun clang`, C17, `-Wall -Wextra -Werror`, CoreFoundation, and SystemConfiguration. No separate DNS-SD library was linked: the macOS 26 SDK exports the public `DNSService*` symbols through libSystem.

## Dynamic Store notifications

Subscription setup for these patterns succeeded outside the restricted sandbox:

State:/Network/Interface/bridge0/.*

A one-second idle run emitted no callback, as expected when configuration did not change. Cable attach/detach event order, duplicates, and delay remain unverified because no physical cable operation was performed.

## Bonjour interface scoping

An ephemeral `_ds4cluster._tcp` registration and browse were both scoped to the `bridge0` index. The service port was passed using `htons(9920)`. Both callbacks succeeded and both `DNSServiceRef` values were deallocated before exit.

```text
bonjour_register_callback error=0
bonjour_browse_callback interface_index=13 error=0
```

## Binding decision

Select Rust crate `system-configuration` 0.7 for production System Configuration access. Use its high-level Dynamic Store API where available and its re-exported low-level bindings for notification/configuration calls. Keep POSIX interface enumeration and DNS-SD behind narrow macOS FFI wrappers.

Rejected alternatives:

- Shell command parsing: localization and output stability are not correctness contracts.
- Private driver-class inspection: private implementation details are not required.
- Full handwritten Core Foundation/System Configuration bindings: excessive unsafe ownership and callback surface.

## Resume condition

Run `network-probe watch 30` while physically detaching and reattaching the Thunderbolt cable. Record only relative timestamps, callback key counts, and the sanitized snapshot after each event. Do not record service UUIDs, IP addresses, or hostnames. Repeat enough times to identify duplicate/out-of-order callbacks and the maximum observed delay.
