# macOS network spike result

## Environment

| Field | Value |
|---|---|
| Date | 2026-08-06 |
| macOS | 26.6 (25G72) |

## Build

`network_probe.c` compiled with `xcrun clang`, C17, `-Wall -Wextra -Werror`, CoreFoundation, and SystemConfiguration. No separate DNS-SD library was linked: the macOS 26 SDK exports the public `DNSService*` symbols through libSystem.

## Sanitized snapshot

```text
interface_index=13
service_found=true service_enabled=true
dynamic_store_link=present dynamic_store_ipv4=present
getifaddrs_ipv4=true up=true prefix_bits=30
```

The snapshot intentionally omits service UUID, interface address, hostname, route contents, and other machine-specific values.

## Dynamic Store notifications

Subscription setup for these patterns succeeded outside the restricted sandbox:

```text
State:/Network/Interface/bridge0/.*
Setup:/Network/Service/.*/.*
```

A one-second idle run emitted no callback, as expected when configuration did not change. Two physical Cable detach/attach cycles were then observed. The first cycle confirmed duplicate callbacks; the second added per-callback Link/IPv4 presence and is the authoritative timing fixture below.

### Detach sequence

Times are relative to the first observed callback, not to the physical action.

| Relative time | Event | Link | IPv4 |
|---:|---|---|---|
| 0 ms | bridge state | present | present |
| 104 ms | bridge state | present | absent |
| 107 ms | duplicate bridge state | present | absent |
| 1,064 ms | service setup, 4 keys | present | absent |

### Attach sequence

Times are relative to the first observed callback after reattachment.

| Relative time | Event | Link | IPv4 |
|---:|---|---|---|
| 0 ms | service setup, 4 keys | present | absent |
| 421–423 ms | bridge state burst, 3 callbacks | present | absent |
| 1,424 ms | bridge state | present | absent |
| 2,048 ms | bridge state | present | present |
| 5,137 ms | duplicate bridge state | present | present |

Observed implications:

- Callback order differs between detach and attach; a single key cannot be treated as the transition itself.
- Bridge state callbacks are duplicated and can arrive in a tight burst.
- Link dictionary presence remained true while IPv4 disappeared, so production code must rescan the full typed snapshot.
- A 500ms debounce coalesces the tight callback burst, while the later IPv4-ready callback still triggers a new rescan.
- After the final callback, snapshot showed service enabled, Link/IPv4 present, IPv4 UP with `/30`, and the same interface index.

## Bonjour interface scoping

An ephemeral `_ds4cluster._tcp` registration and browse were both scoped to the `bridge0` index. The service port was passed using `htons(9920)`. Both callbacks succeeded and both `DNSServiceRef` values were deallocated before exit.

```text
bonjour_register_callback error=0
bonjour_browse_callback interface_index=13 error=0
```

## Binding decision

Select Rust crate `system-configuration` 0.7 for production System Configuration access. Use its high-level Dynamic Store API where available and its re-exported low-level bindings for notification/configuration calls. Keep POSIX interface enumeration and DNS-SD behind narrow macOS FFI wrappers.

Rejected alternatives:

- Shell command parsing: localization and output stability are not correctness contracts.
- Private driver-class inspection: private implementation details are not required.
- Full handwritten Core Foundation/System Configuration bindings: excessive unsafe ownership and callback surface.
